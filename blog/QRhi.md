# QRhi

## 先说"理论上"——能到什么程度

QRhi 提供的底层能力：

| UE/Unity 需要什么          | QRhi 有没有                                        |
| -------------------------- | -------------------------------------------------- |
| 画三角形/网格              | ✅ `QRhiBuffer` + `QRhiGraphicsPipeline`            |
| 着色器（HLSL/GLSL→SPIR-V） | ✅ `QRhiShaderResourceBindings` + `QRhiShaderStage` |
| 纹理/采样器                | ✅ `QRhiTexture` + `QRhiSampler`                    |
| 渲染到纹理（FBO）          | ✅ `QRhiTextureRenderTarget`                        |
| 多渲染目标（MRT）          | ✅                                                  |
| 计算着色器                 | ✅（Vulkan/DX12/Metal 后端）                        |
| 多线程命令录制             | ✅ `QRhiCommandBuffer`                              |
| 资源屏障/同步              | ✅ 内部处理                                         |
| 交换链/窗口呈现            | ✅ `QRhiSwapChain`                                  |

**从纯渲染角度：QRhi 的能力覆盖 UE/Unity 渲染后端 90% 以上的需求。**

所以理论上你完全可以：

```
QRhi
 ├─ 场景图（Scene Graph）
 ├─ 材质系统（Material / Shader Permutation）
 ├─ 灯光/阴影
 ├─ 后处理（Bloom/DOF/TAA）
 ├─ 动画系统
 ├─ 物理（接 Bullet/PhysX）
 ├─ 音频
 ├─ 资源管线（模型/贴图导入）
 └─ 编辑器 UI（用 Qt Widgets/QML）
```

这就是一个引擎。

## 再说"实际上"——差距在哪

### QRhi 能给你的（免费）

- 跨平台图形抽象 ✅
- 窗口/交换链管理 ✅
- 资源创建/销毁 ✅
- 着色器编译管线（Qt Shader Tools）✅

### UE/Unity 额外有的（你要自己写）

| 系统                                 | 工作量估算 |
| ------------------------------------ | ---------- |
| 场景管理（BVH/八叉树/剔除）          | 3~6 个月   |
| 材质/Shader 变体系统                 | 3~6 个月   |
| 灯光 + 阴影（CSM/SSAO）              | 3~6 个月   |
| 后处理链                             | 2~3 个月   |
| 动画系统（骨骼/蒙皮/Blend Tree）     | 6~12 个月  |
| 物理集成                             | 2~3 个月   |
| 资源导入管线（FBX/glTF/贴图压缩）    | 6~12 个月  |
| 编辑器（场景视图/属性面板/撤销重做） | 12~24 个月 |
| 脚本系统（Lua/C#/蓝图）              | 6~12 个月  |
| 资产数据库/打包/热更新               | 6~12 个月  |

**光渲染那层 QRhi 帮你搞定了，但引擎 ≠ 渲染器。**

## 现实中的参考案例

### 用 QRhi 做引擎的：

- **Qt Quick 3D**（Qt 官方，基于 QRhi）
- **Qt 3D Studio**（已停，但证明可行）
- **一些工业可视化/仿真软件**（内部引擎，不公开）

### 用轻量 RHI 做引擎的：

- **Godot 4**：自己写了 RenderingDevice（类似 RHI），支持 Vulkan/DX12/Metal/OpenGL
- **Source 2（Valve）**：自家 RHI
- **id Tech 7**：自家 RHI

## 一句话总结

> **QRhi 给你的是"画布 + 画笔"，你能画出和 UE 一样的画面——但 UE 还有场景编辑器、材质编辑器、动画系统、物理、音频、脚本、资源管线、打包部署……这些是 QRhi 不管的。**

QRhi ≈ 引擎的"显卡驱动抽象层"

引擎 = QRhi + 场景 + 材质 + 灯光 + 动画 + 物理 + 编辑器 + 工具链 + 资产管线

## 你该不该走这条路

| 你的目标                        | 建议                                   |
| ------------------------------- | -------------------------------------- |
| 学图形/引擎架构                 | ✅ 用 QRhi 写个迷你引擎，超好的学习项目 |
| 做产品/工具（工业可视化、仿真） | ✅ QRhi + Qt 很合适                     |
| 做商业游戏                      | ❌ 直接用 UE/Unity/Godot，别重复造轮子  |
| 做开源引擎                      | ⚠️ 可行但要做好长期投入的准备           |
